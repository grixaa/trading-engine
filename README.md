# Trading Engine

REST-сервис для непрерывной торговли акциями, облигациями и валютными парами с лимитными заявками.

## Переменные окружения (.env)

- `TRADING_DB_URL` — JDBC-адрес базы
- `TRADING_DB_USER` — пользователь PostgreSQL
- `TRADING_DB_PASSWORD` — пароль пользователя PostgreSQL
- `TRADING_HTTP_PORT` — HTTP-порт приложения

## Документация REST API

Swagger UI и OpenAPI доступны на порту приложения, заданном в `application.yml` через `server.port`. Установите `TRADING_HTTP_PORT` в окружении процесса, чтобы изменить порт.

- Swagger UI — `/swagger-ui.html`
- OpenAPI JSON — `/v3/api-docs`

Пути задаются в том же файле через `springdoc.swagger-ui.path` и `springdoc.api-docs.path`.

При вызове методов работы с заявками и просмотра балансов укажите идентификатор участника в заголовке `X-User-Id`.

### Справочник активов

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `POST /api/assets` | Создать актив с кодом `code` и типом `CURRENCY` или `SECURITY`. | `201 Created`, актив и заголовок `Location` |
| `GET /api/assets` | Получить список активов. | `200 OK`, массив активов |
| `GET /api/assets/{code}` | Получить актив по коду. | `200 OK`, актив |

Пример тела запроса для создания акции как актива. Для рубля используйте `{"code":"RUB","type":"CURRENCY"}`.

```json
{"code":"SBER","type":"SECURITY"}
```

Код содержит от 1 до 32 символов. Первый символ — заглавная латинская буква или цифра. После него также допустимы точка, подчёркивание и дефис.

### Торговые инструменты и стакан

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `POST /api/instruments` | Создать инструмент на основе существующих активов. Тип инструмента — `STOCK`, `BOND` или `FX`. | `201 Created`, инструмент и заголовок `Location` |
| `GET /api/instruments` | Получить список инструментов. | `200 OK`, массив инструментов |
| `GET /api/instruments/{seccode}` | Получить инструмент по коду. | `200 OK`, инструмент |
| `GET /api/instruments/{seccode}/order-book` | Получить стакан. Параметр `depth` задаёт число ценовых уровней на сторону, от 1 до 100, по умолчанию 10. | `200 OK`, объект с `seccode`, `bids` и `asks` |

В стакане каждый уровень содержит цену и суммарный открытый объём в лотах. Покупки идут от большей цены к меньшей, продажи — от меньшей к большей.

Пример создания инструмента после регистрации активов `SBER` и `RUB`.

```json
{
  "seccode": "SBER",
  "type": "STOCK",
  "baseAsset": "SBER",
  "quoteCurrency": "RUB",
  "lotSize": 10,
  "minStep": 0.01
}
```

`baseAsset` — актив, который покупают и продают, `quoteCurrency` — валюта цены и расчёта. Для `STOCK` и `BOND` базовый актив должен иметь тип `SECURITY`, для `FX` — `CURRENCY`. `lotSize` задаёт количество единиц актива в лоте, `minStep` — шаг цены.

### Счета и балансы

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `PUT /api/accounts/{userId}` | Открыть счёт участника. Повторный вызов даёт тот же результат. | `204 No Content` |
| `POST /api/accounts/{userId}/deposits` | Зачислить зарегистрированный актив на открытый счёт, указав `asset` и `amount`. | `200 OK`, баланс этого актива |
| `GET /api/balances` | Получить балансы участника из заголовка `X-User-Id`. | `200 OK`, массив объектов с `asset`, `available` и `reserved` |

Пример пополнения счёта рублями.

```json
{"asset":"RUB","amount":10000}
```

Для зачисления бумаг используйте код бумаги, например `{"asset":"SBER","amount":20}`. Количество бумаг указывается целым числом в штуках. Пополнение увеличивает `available`, а повторный `POST` зачисляет сумму повторно.

### Заявки

Для всех запросов к `/api/orders` передавайте заголовок `X-User-Id`.

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `POST /api/orders` | Выставить лимитную заявку. Сопоставление выполняется сразу, свободный остаток остаётся в стакане. | `201 Created`, состояние заявки после обработки и заголовок `Location` |
| `GET /api/orders/{id}` | Получить заявку по идентификатору. | `200 OK`, заявка |
| `GET /api/orders` | Получить реестр заявок участника. Можно указать `seccode`, `side`, `status`, `beforeId` и `limit`. | `200 OK`, страница заявок |
| `PATCH /api/orders/{id}` | Изменить цену, открытый остаток или оба поля. Ранее исполненный объём сохраняется. | `200 OK`, состояние заявки после обработки |
| `DELETE /api/orders/{id}` | Отменить открытый остаток заявки и освободить резерв. Уже записанные сделки сохраняются. | `200 OK`, отменённая заявка |

Пример покупки трёх лотов. Цена указана за одну бумагу, количество — в лотах. Цена должна быть кратна `minStep`.

```json
{"seccode":"SBER","side":"BUY","price":250.50,"quantity":3}
```

Пример изменения только открытого остатка до двух лотов.

```json
{"remaining":2}
```

Допустимые стороны — `BUY` и `SELL`. Возможные статусы заявки — `OPEN`, `PARTIALLY_FILLED`, `FILLED` и `CANCELLED`. Просмотр, изменение и отмена отдельной заявки доступны её владельцу.

### Реестр сделок

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `GET /api/trades` | Получить совершённые сделки. Параметр `seccode` фильтрует по инструменту, `orderId` — по заявке любой стороны. Доступны `beforeId` и `limit`. | `200 OK`, страница сделок |

В записи сделки есть идентификаторы заявки покупки и заявки продажи, инструмент, цена исполнения, количество в лотах и время исполнения.

### Пагинация и ошибки

Реестры заявок и сделок возвращают `items` и `nextBeforeId`. Записи идут по убыванию идентификатора. Размер страницы `limit` — от 1 до 100, по умолчанию 20. Передайте полученный `nextBeforeId` в `beforeId` следующего запроса с теми же фильтрами. Значение `null` означает последнюю страницу.

Ошибки передаются в формате Problem Details. Некорректный запрос даёт `400`, отсутствующий ресурс или чужая заявка — `404`, конфликт состояния или недостаточный остаток — `409`. У бизнес-ошибок есть поле `code`, например `INVALID_PRICE` или `INSUFFICIENT_BALANCE`.
